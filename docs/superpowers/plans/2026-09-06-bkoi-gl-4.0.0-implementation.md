# Implementation Plan: bkoi-gl 4.0.0

Spec: `docs/superpowers/specs/2026-09-06-bkoi-gl-4.0.0-maplibre-v6-design.md`
Reference implementation: `../react-bkoi-gl` (test architecture to mirror).

Each phase ends with its verification gate. Do not start the next phase until
the gate passes.

Standing rules (from sdk-development):

- **Regression rule:** published 3.3.0 is the behavior contract. When
  something breaks after the bump, diff against 3.3.0's behavior and match —
  don't invent new behavior mid-version.
- **Docs are a contract:** every README example must run against the built
  artifact. Automated in Phase 6; manual signal already in Phase 1.
- **Agent never commits/pushes/publishes.** Suggest commit messages, wait.

## Phase 1 — maplibre v6 migration (major-upgrade protocol)

1. `npm install maplibre-gl@6.6.0 --save-exact` (dependency, bundled).
2. `npm run typecheck`; fix compile errors in `src/` (index.ts,
   controls/Minimap.ts, controls/ToggleButton.ts, utils/*).
3. Check `maplibre-gl-draw@1.6.9` compat with v6; bump only if broken.
4. Grep `src/` for `.maplibregl-` class selectors and verify against v6 DOM
   markup; check event-payload contracts (fields the README promises, e.g.
   `lngLat` on drag) still exist — v6 dropped fields from some events;
   the wrapper must enrich/normalize anything the docs promise.
5. Mount-timing: guard style-dependent logic with ready-flags/retries, not
   one-shot listeners (`styledata` can fire before the style is queryable).
6. `npm run build`; all four formats emit; grep dist for `require(` / `from`
   specifiers — maplibre must be fully bundled (zero externals expected).
7. **README-matrix smoke (fastest breakage signal):** extract every fenced
   example from README.md, run each manually in a scratch page against the
   built ESM bundle with `BARIKOI_API_KEY`. An example that crashes is a
   contract break — fix before anything else.

Gate: typecheck + lint + build green; every README example runs against dist.

## Phase 2 — replace Jest with vitest — ✅ DONE (110 tests, 100% coverage enforced, 9/9 stable full-suite runs)

> Coverage: 100% statements/branches/functions/lines enforced via thresholds.
> Unit project drives wrapper branches with a mocked maplibre-gl + draw;
> browser project keeps real-rendering coverage. Source hardening along the
> way: construction guarantees moved to the type level (containerStyle
> invariant), dead defensive fallbacks removed, innerText → textContent.

1. Delete `test/` and `jest.config.cjs`.
2. Remove devDeps: jest, jest-environment-jsdom, ts-jest, @types/jest,
   babel-*, regenerator-runtime. Add: vitest, @vitest/browser,
   @vitest/browser-playwright, playwright.
3. `vitest.config.ts`, two projects (mirror react-bkoi-gl minus React):
   - `unit` (jsdom): config, validator, utils, constants.
   - `browser` (headless Chromium): real rendering — minimap, style drawer,
     navigation, geolocate, fullscreen, attribution, scale, polygon drawing.
4. Browser-mode pitfalls (from react-bkoi-gl hard-won):
   - `waitFor`/event registration for async readiness — never polling
     executors; a hang means a registration race, not a timeout to bump.
   - Per-file timeouts via `vi.setConfig({ testTimeout })` (no module-level
     `test.setTimeout`).
   - Mocks track the real maplibre v6 API; when a mocked test fails after a
     legit change, suspect the mock first.
   - Stability claims need 6–8× repeated full-suite runs.
5. Coverage: v8 provider wired into the `test` script (every run reports,
   ≥80% target, exclude `src/types/**` and `.d.ts`).
6. API key: `BARIKOI_API_KEY` via env (port `loadEnvKey`); tests fail loudly
   when missing, never skip silently.
7. Scripts: `test` (unit + browser + coverage), `test:unit`, `test:browser`,
   `playwright:install`; update `prepublishOnly`.

Gate: `npm run test:unit` and `npm run test:browser` green, repeated run
stable.

## Phase 3 — Playwright e2e vs built dist

1. Port react-bkoi-gl's `playwright.config.ts` shape: workers 1, 60s
   timeout, webServer = vite serving `tests/e2e/app`, fixed port.
2. `tests/e2e/app`: Vite host importing the **built dist**; a plain
   `umd.html` loading `dist/umd/bkoi-gl.js` via script tag. Verify the host
   resolves the package name to `dist/` (not a stale installed copy); import
   **every published entry point** — `bkoi-gl` and `bkoi-gl/style.css`.
3. Env via the app's real `.env` mechanism (Vite env); commit `.env.example`,
   gitignore `.env` precisely. No `window.__*__` globals.
4. Case registry: feature matrix in README is the source of truth — every
   documented feature gets an e2e case:
   - map.spec: init, style load, move/zoom events (with payload fields)
   - controls.spec: each control mounts and interacts
   - draw.spec: polygon drawing
   - formats.spec: UMD script-tag page renders
5. Scripts: `e2e` (build && playwright test), `e2e:serve`.

Gate: `npm run e2e` green against rebuilt dist.

## Phase 4 — framework matrix — ✅ DONE (6/6 apps, npm; Nuxt 3 + Angular 21 pinned for Node 25)

> Landed alongside a required migration fix: maplibre v6's worker is a separate
> file resolved from `import.meta.url`, which dies once a consumer bundles the
> library. bkoi-gl now ships one self-contained worker, constructs it as a
> same-origin Blob synchronously (`src/worker-setup.ts`), and exports
> `bkoi-gl/worker` for strict-CSP consumers. See `scripts/build-worker.mjs`.
> The matrix is also what caught it — the e2e host had been serving dist as
> Vite `publicDir`, masking the missing asset with an HTML fallback.

1. Port `tests/framework/`: `run.mjs`, `lib.mjs`, `verify.mjs` (skip
   `review.mjs` — deferred by spec).
2. Six minimal apps: react-vite, vue-vite, nuxt, angular (pinned major),
   svelte-vite, sveltekit. Per app: install deps with chosen PM, install the
   packed tarball (tarball method — never `npm link`), build, serve,
   headless verify map renders.
3. Script: `test:framework` with `--only=` / `--pm=` flags.

Gate: `npm run test:framework` green on all six apps (npm).

## Phase 5 — resolution + pack smoke

1. Port `scripts/test-resolution.mjs`: per PM (npm, pnpm, yarn, bun) temp
   sandbox, install tarball, import `bkoi-gl` by name, resolve
   `./style.css` subpath to a real file.
2. Port `scripts/test-pack.mjs` (full pack smoke):
   - build fresh, `npm pack`, extract tarball into temp sandbox;
   - import by name (exercises the exports map), assert key exports with
     `typeof !== 'undefined'`, styles resolve;
   - test both shipped module paths (ESM import; CJS `require` of
     `index.cjs`) — maplibre v6 is ESM-only upstream, but we bundle, so CJS
     must work by construction; if it can't, document the constraint;
   - contents check: 4 dist formats, style css, README, LICENSE.
3. Scripts: `test:resolution`, `test:pack`.

Gate: resolution green on 4 PMs; pack smoke green; contents verified.

## Phase 6 — README validation + package hygiene

1. README example validation: every fenced example becomes an automated e2e
   case (executable specs) — no example left manual-only.
2. `npx publint` — fix exports/types warnings.
3. Dependency hygiene: exact pins for maplibre-gl (6.6.0) and friends;
   `npm audit --audit-level high`; sweep dead package.json scripts and
   stray files (every script runnable and referenced).
4. README: maplibre v6 base note; feature matrix updated to match e2e cases.

Gate: README-matrix e2e automated and green; publint clean; audit pass.

## Phase 7 — release prep

1. CHANGELOG: `## [4.0.0] - <date>` entry — maplibre v6 under the hood,
   migration notes for any breaking surface, test overhaul (user-facing
   outcomes only, no process minutiae). Changelog is the single source of
   truth for the version: package.json version set from it, never
   hand-bumped independently.
2. Pre-publish gate in order: typecheck → lint → unit → browser → e2e vs
   dist → README validation → publint → pack smoke → audit → CHANGELOG.
3. **User reviews, commits, and publishes manually.** Agent suggests the
   commit message and waits.

Gate: full `prepublishOnly` chain green; user sign-off.
